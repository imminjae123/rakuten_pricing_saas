1. 推奨ディレクトリ構成

採用アーキテクチャ: Layered Architecture（≒ Clean Architecture 簡略版）
api（Router/Schema） → services（Use-Case/Business Logic） → repositories（DB I/O） → models（ORM/Domain）
Worker・Scheduler は workers/ に分離し、HTTP層とは独立して動作させる。

主要ライブラリの選定理由

ライブラリ選定理由代替案との比較
asyncpg psycopg2 比で 3〜5× 高速。SET LOCAL RLS コマンドを同一接続上で実行可能。SQLAlchemy async engine の公式推奨ドライバ psycopg3 も可だが asyncpg の方が実績豊富
pydantic-settings .env を型安全に読む。model_validator で DATABASE_URL の prefix 検証が可能 python-dotenv は型なし
redis[hiredis] v5 で aioredis が統合。asyncio / 同期両方のクライアントが統一 API で使える（Celery は同期コンテキストで使用） aioredis 単体は deprecated
celery beat スケジューラ内蔵。LINE push タスクの retry/ETA 制御が容易。Upstash Redis (TLS) に対応 RQ はシンプルだが beat 相当機能なし。APScheduler は状態管理が弱い
httpx async context manager 対応。AsyncClient + limits でコネクションプール管理。Yahoo! Shopping API throttle と相性良好 aiohttp は API が煩雑
alembic async engine を使った run_sync パターンで RLS policy DDL も管理可能 必須。代替なし

環境変数管理方針

方針詳細
型安全pydantic-settings app/config.py に class Settings(BaseSettings) を定義。起動時に全変数を検証し、型エラーは即クラッシュ（Fail-Fast）。model_validator で DATABASE_URL が postgresql+asyncpg:// 始まりか検証。
機密分離Secrets SECRET_KEY, LINE_CHANNEL_ACCESS_TOKEN, YAHOO_CLIENT_ID は .env に書かず、本番環境では Render / Railway の環境変数 UI またはシークレットマネージャーから注入。
環境切り替えAPP_ENV APP_ENV=development 時のみ DEBUG=true を許可。production 時は DEBUG を強制 false、SQLAlchemy echo=False。
シングルトンlru_cache @lru_cache() + get_settings() パターンで Settings インスタンスを1つに固定。テスト時は get_settings.cache_clear() で差し替え可能。 
# app/config.py の骨格
from functools import lru_cache
from pydantic_settings import BaseSettings, SettingsConfigDict
from pydantic import model_validator

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8")

    app_env: str = "development"
    database_url: str
    redis_url: str
    secret_key: str
    yahoo_client_id: str
    line_channel_access_token: str
    ...

    @model_validator(mode="after")
    def validate_db_driver(self) -> "Settings":
        if not self.database_url.startswith("postgresql+asyncpg://"):
            raise ValueError("DATABASE_URL must use asyncpg driver")
        return self

@lru_cache()
def get_settings() -> Settings:
    return Settings()

4. JWT → tenant_id 抽出 + RLS 適用設計

4-1. 全体フロー

HTTP Request
Authorization: Bearer → Depends(get_current_user)

4-2. CurrentUser スキーマ

# app/dependencies/auth.py
from dataclasses import dataclass
from enum import StrEnum

class Role(StrEnum):
    OWNER   = "OWNER"
    MANAGER = "MANAGER"
    VIEWER  = "VIEWER"

@dataclass(frozen=True)
class CurrentUser:
    user_id:   str
    tenant_id: str   # 全 DB クエリの where 条件 + RLS に使用
    role:      Role

4-3. JWT デコード Dependency

# app/dependencies/auth.py
from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from jose import JWTError, jwt
from app.config import get_settings

bearer_scheme = HTTPBearer()

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
    settings = Depends(get_settings),
) -> CurrentUser:
    try:
        payload = jwt.decode(
            credentials.credentials,
            settings.secret_key,
            algorithms=[settings.jwt_algorithm],
        )
        tenant_id: str | None = payload.get("tenant_id")
        user_id:   str | None = payload.get("sub")
        role:      str | None = payload.get("role")
        if not tenant_id or not user_id:
            raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Invalid token claims")
        return CurrentUser(user_id=user_id, tenant_id=tenant_id, role=Role(role))
    except JWTError:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Could not validate credentials")

4-4. RLS 適用 Session Dependency（最重要）

重要: SET LOCAL は トランザクション内 でのみ有効。 セッションが終了するとリセットされる。async with session.begin() の中で必ず実行すること。 Connection Pool を使う場合、接続が別テナントに再利用される前に RLS 設定がリセットされることを保証する必要がある。 
# app/dependencies/db.py
from collections.abc import AsyncGenerator
from sqlalchemy.ext.asyncio import AsyncSession
from fastapi import Depends
from app.infrastructure.database import async_session_factory
from app.dependencies.auth import CurrentUser, get_current_user

async def get_tenant_session(
    current_user: CurrentUser = Depends(get_current_user),
) -> AsyncGenerator[AsyncSession, None]:
    """
    1. 新しい AsyncSession を取得
    2. トランザクション開始と同時に SET LOCAL でテナントを設定
    3. PostgreSQL RLS が app.current_tenant_id を参照してフィルタリング
    4. finally ブロックで必ずセッションをクローズ（接続プールに返却）
    """
    async with async_session_factory() as session:
        async with session.begin():
            await session.execute(
                "SET LOCAL app.current_tenant_id = :tid",
                {"tid": current_user.tenant_id},
            )
            try:
                yield session
                # session.begin() の __aexit__ が commit
            except Exception:
                await session.rollback()
                raise

4-6. RBAC ガード（Role チェック Dependency）

# app/dependencies/auth.py
from fastapi import HTTPException, status

def require_role(*allowed_roles: Role):
    """
    使い方: Depends(require_role(Role.OWNER, Role.MANAGER))
    """
    async def _check(current_user: CurrentUser = Depends(get_current_user)):
        if current_user.role not in allowed_roles:
            raise HTTPException(
                status.HTTP_403_FORBIDDEN,
                f"Required role: {[r.value for r in allowed_roles]}",
            )
        return current_user
    return _check

4-7. 非同期安全性チェックリスト

リスク対策
Connection Pool でのテナント混在 SET LOCAL（トランザクションスコープ）を使用。SET SESSION は禁止（接続再利用時にリークする）
Celery Worker での RLS 欠落 Worker タスクは JWT ではなく tenant_id を直接引数で受け取り、Worker 内でも get_tenant_session 相当の初期化を実行
Alembic マイグレーション時の RLS バイパス alembic/env.py では BYPASSRLS 権限を持つ管理ユーザーで接続し、アプリユーザーとは DB ロールを分離
Audit Log の RLS 適用 Audit Log は INSERT のみ。RLS は SELECT にも適用されているため、自テナントのログしか閲覧できない
cost / margin の JSON シリアライズ漏洩 schemas/product.py の Response Schema から cost, min_margin フィールドは VIEWER ロール向けに除外
