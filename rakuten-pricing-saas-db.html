RLS 設計方針 + Append-Only 保護

DB ロール分離

ロール権限用途
migration_userBYPASSRLS + スキーマオーナーAlembic マイグレーション専用
app_userSELECT/INSERT/UPDATE/DELETE (RLS対象)FastAPI アプリ接続ユーザー

RLS ポリシー (全テナントスコープテーブル共通)

-- Alembic migration 0002 で適用
ALTER TABLE {table} ENABLE ROW LEVEL SECURITY;
ALTER TABLE {table} FORCE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON {table}
    AS PERMISSIVE FOR ALL TO app_user
    USING (
        tenant_id = current_setting('app.current_tenant_id', true)::uuid
    )
    WITH CHECK (
        tenant_id = current_setting('app.current_tenant_id', true)::uuid
    );
SET LOCAL vs SET SESSION: アプリ層は必ず SET LOCAL app.current_tenant_id = '<uuid>' を使用。
SET SESSION はトランザクション終了後も設定が残留し、コネクションプール再利用時にクロステナントリークが発生する。

Append-Only トリガー

CREATE OR REPLACE FUNCTION enforce_append_only()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    IF TG_OP = 'UPDATE' THEN
        RAISE EXCEPTION 'UPDATE is not allowed on append-only table "%"', TG_TABLE_NAME
            USING ERRCODE = 'restrict_violation';
    END IF;
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'DELETE is not allowed on append-only table "%"', TG_TABLE_NAME
            USING ERRCODE = 'restrict_violation';
    END IF;
    RETURN NULL;
END;
$$;

-- price_histories と audit_logs に適用
CREATE TRIGGER trg_price_histories_append_only
    BEFORE UPDATE OR DELETE ON price_histories
    FOR EACH ROW EXECUTE FUNCTION enforce_append_only();

-- audit_logs は追加でアプリユーザーの権限もREVOKE (二重防護)
REVOKE UPDATE, DELETE ON audit_logs FROM app_user;
REVOKE UPDATE, DELETE ON price_histories FROM app_user;

設計上の重要ポイント

ポイント実装箇所
全リレーションは lazy="raise"N+1クエリを防ぐ。明示的な selectinload() / joinedload() を強制
UUID は server_default=gen_random_uuid()INSERT前のDB往復ゼロ。asyncpg との相性最良
PriceHistory / AuditLog に updated_at なしスキーマレベルで不変性を示す
Numeric(12,2) for cost/price浮動小数点誤差排除 (金額計算の必須要件)
CompetitorProduct は RLS 非対象グローバルカタログ。ただし ProductMapping と PriceHistory で間接的にテナント分離
